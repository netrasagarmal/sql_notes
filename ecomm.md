# Problem Statement: Online Marketplace Order Analytics System

You are designing a database for an **online marketplace platform** where customers purchase products from different sellers.

The system must support:

* Customer registration
* Product catalog management
* Order placement
* Tracking order items
* Revenue analytics and product performance

Data engineers and analysts will frequently run queries to:

* Analyze sales performance
* Identify top customers
* Track product popularity
* Monitor order trends
* Generate seller revenue reports

The database must support both **transactional queries and analytical SQL queries**.

---

# Entities Overview

The system will contain **4 core tables**:

1. Customers
2. Products
3. Orders
4. Order_Items

This design supports:

* **Primary Keys**
* **Foreign Keys**
* **Composite Keys**
* Multiple **data types**
* **One-to-many relationships**
* Analytical use cases

---

# ER Diagram (Conceptual)

```
Customers
   |
   | 1
   |
   |------< Orders
               |
               | 1
               |
               |------< Order_Items >------ Products
                       many              1
```

Meaning:

* One customer can place many orders
* One order contains multiple items
* One product can appear in many order items

---

# Table Design

---

# 1. Customers Table

Stores customer information.

```sql
CREATE TABLE Customers (
    customer_id BIGINT PRIMARY KEY,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    email VARCHAR(120) UNIQUE,
    phone VARCHAR(15),
    city VARCHAR(50),
    country VARCHAR(50),
    signup_date DATETIME
);
```

### Important Concepts Covered

* Primary Key
* Unique constraint
* String data types
* Datetime

---

# 2. Products Table

Stores product catalog information.

```sql
CREATE TABLE Products (
    product_id BIGINT PRIMARY KEY,
    product_name VARCHAR(120),
    category VARCHAR(50),
    price DOUBLE,
    stock_quantity INT,
    created_at DATETIME
);
```

### Important Concepts Covered

* Primary key
* Floating numeric values
* Inventory tracking

---

# 3. Orders Table

Represents a purchase order placed by a customer.

```sql
CREATE TABLE Orders (
    order_id BIGINT PRIMARY KEY,
    customer_id BIGINT,
    order_date DATETIME,
    order_status VARCHAR(20),
    total_amount DOUBLE,
    
    FOREIGN KEY (customer_id) REFERENCES Customers(customer_id)
);
```

### Important Concepts

* Foreign Key
* One-to-many relationship
* Transactional data

---

# 4. Order_Items Table

Stores each product inside an order.

```sql
CREATE TABLE Order_Items (
    order_item_id BIGINT PRIMARY KEY,
    order_id BIGINT,
    product_id BIGINT,
    quantity INT,
    unit_price DOUBLE,
    
    FOREIGN KEY (order_id) REFERENCES Orders(order_id),
    FOREIGN KEY (product_id) REFERENCES Products(product_id)
);
```

### Important Concepts

* Bridge table
* Many-to-many relationship
* Analytical metrics (revenue)

---

# Final ER Relationship Summary

| Table     | Relationship | Table       |
| --------- | ------------ | ----------- |
| Customers | 1 → Many     | Orders      |
| Orders    | 1 → Many     | Order_Items |
| Products  | 1 → Many     | Order_Items |

# 1. Find top 3 products by revenue in each category

```sql
SELECT *
FROM (
    SELECT p.category,
           p.product_name,
           SUM(oi.quantity * oi.unit_price) AS revenue,
           ROW_NUMBER() OVER (PARTITION BY p.category ORDER BY SUM(oi.quantity * oi.unit_price) DESC) AS rn
    FROM Products p
    JOIN Order_Items oi ON p.product_id = oi.product_id
    GROUP BY p.category, p.product_name
) t
WHERE rn <= 3;
```

# 10. Identify products contributing to top 80% revenue (Pareto)

```sql
WITH product_rev AS (
SELECT product_id,
       SUM(quantity*unit_price) revenue
FROM Order_Items
GROUP BY product_id
),
ranked AS (
SELECT *,
       SUM(revenue) OVER(ORDER BY revenue DESC) cum_rev,
       SUM(revenue) OVER() total_rev
FROM product_rev
)
SELECT *
FROM ranked
WHERE cum_rev <= total_rev * 0.8;
```
